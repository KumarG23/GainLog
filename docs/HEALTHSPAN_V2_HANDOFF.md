# Healthspan V2 — Jarvis handoff

Branch: `feat/healthspan-v2`. Based on the reviewed `main` commit `66d15521`.

## Scope

- Five-tab product shell: Today, Health, Train, Fuel, Trends. Today is the launch route.
- Existing workout logger moved byte-for-byte from `app/(tabs)/index.tsx` to `app/(tabs)/workout.tsx`. Existing food diary, history, strength stats, tracking/goals, reviews and session details remain functional drill-downs.
- Reusable screen/card/chart primitives and a global Quick Log sheet. Weight submission is explicit and duplicate-guarded; workout/food actions open the existing editors.
- Today uses an in-memory, abortable, validated V2 query with foreground refresh, timeout, date rollover, a visible retrieval timestamp and stale/error handling. It does not request provider synchronization or write model outputs.
- Stress is a full-day timeline with a snapshot marker, interval detail and named sleep/exercise/movement/warm-up/missing/future states. It is **retrospective physiological activation, not live or emotional stress**.
- Healthspan compares seven completed days with the preceding 28. Missing data stays missing, duplicate dates are resolved, sparse windows do not get directional comparisons, and source transitions suppress deltas. No biological age, longevity score or causal correlations are invented.
- Train reuses the saved calendar templates and actual workout records; rest is not a failure. Fuel uses recorded intake and saved goals, and does not assume unlogged days mean zero consumption.
- `BUILD YOUR HEALTHSPAN` branding, editable Baseline G SVGs and deterministic PNG assets generated by app.config.js using Node built-ins, including adaptive foreground and monochrome assets. App configuration changes only when V2 UI is enabled. Package IDs, permissions and database schema are unchanged.

## Enable / rollback

The full shell is enabled **only** by `EXPO_PUBLIC_GAINLOG_V2_UI=1` at bundle build time. `EXPO_PUBLIC_GAINLOG_V2_TODAY` remains the old single-tab preview flag; the full UI takes precedence, leaving the old Health route available for tracking/goals.

A new `healthspan-preview` EAS profile extends `preview`, enables the UI, selects an Android APK, and uses the existing remote auto-increment mechanism. `development`, `preview` and `production` are not silently switched to V2.

1. Check Jarvis's working tree. Preserve unrelated/local work; do not reset, force-push or blindly overwrite it.
2. Fetch and check out `origin/feat/healthspan-v2`, review changes, and keep the existing API/environment configuration.
3. Run `npm ci`, `npm test`, `npx tsc --noEmit`, and `npm run lint`.
4. Export both modes before building. For the preview use `EXPO_PUBLIC_GAINLOG_V2_UI=1 EXPO_PUBLIC_GAINLOG_V2_TODAY=0 npx expo export --platform web --platform android`.
5. Build with `npx eas-cli build --platform android --profile healthspan-preview` (or the existing local native build procedure with the same flags).
6. Install on the existing device/app ID. Do not reset application data, resync providers, change scoring formulas, or run new database migrations for this UI change.

Rollback: build from the same branch with `EXPO_PUBLIC_GAINLOG_V2_UI=0` (and the previous single-tab flag setting). The old navigation and old icon configuration remain available. There is no new persisted UI or model state to migrate back.

## Release gates

Automated verification is defined in `.github/workflows/healthspan-ui.yml`; it has read-only repository permissions and performs no deployment or signing. The build artifacts are unsigned JS/web review outputs, **not an APK**. The authoritative result is the check run for the exact candidate commit, not an earlier passing run.

Local review has run all 203 Node tests and syntax validation of changed TS/TSX. Full dependency-locked type/lint/bundle verification is performed by CI. Update the pull request with that run's result before merging.

Native acceptance still requires Jarvis and the device:

- Launch goes to Today; five tabs remain readable at normal and enlarged system text sizes.
- Every metric/detail link works. Hidden editor routes offer a back action. Check Android hardware back and edge-to-edge insets.
- Open Workout, Food and Weight from Quick Log. Save one deliberate test entry only with the user's approval; verify persistence and no duplicates. Existing notification/deep links still open the food diary.
- Weight keyboard does not obscure the Save button. Cancel does not save.
- Check empty account, missing sleep/HRV, stress warm-up, rest day, partially observed day, offline first load, refresh failure with cached values, and overnight date change. Missing or unavailable must not look like a measured zero or a healthy score.
- Check the launcher icon in default and themed-icon modes and the native splash. Confirm the new APK can upgrade the previous installation.
- No medical, emotional-stress or readiness-prediction claims are added by the UI. Calibration evidence is not predictive validation.

## Deliberate limits

This is the first full-shell preview. Existing detailed charts and entry forms retain their working interaction patterns; overview cards lead to the relevant detailed chart category. The source model still reports a row-level effective source, not per-metric device provenance. It cannot identify an individual metric’s device when that provenance is absent. Blood pressure, labs, causal personal-experiment analysis and a journal backend are not fabricated or introduced.

Do not claim a signed APK, native device QA, production API smoke test or deployment has happened merely because the bundle check passes. Jarvis owns those final delivery steps.

## Brand asset generation

`node scripts/brand-assets.cjs` generates the launcher icon, adaptive foreground, themed monochrome icon and favicon without additional dependencies or a network request. V2 app.config.js invokes it automatically before Expo processes assets. Generated PNGs are ignored; the generator and editable SVG design sources are tracked. The marker is keyed to the generator hash, so a geometry change invalidates cached assets. No manual image-export step is required for Jarvis.
